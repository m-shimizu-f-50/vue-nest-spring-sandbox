# 学習メモの下書き

メモは**続かないもの**という前提で作る。
下書きまで用意して、本人は自分の言葉に直すだけにする。ただし**全部を代筆はしない**。

## 流れ

1. このセッションでやったことを振り返る
2. `docs/00-memo-template.md` があればその項目に沿う。なければ下の項目を使う
3. ファイル名は `YYYY-MM-DD-テーマ.md`（例: `2026-10-05-vue3-ref-reactive.md`）
4. 書いたら、**空で渡した欄がどこか**を明示して伝える

## 項目ごとの扱い

| 項目 | 扱い |
|---|---|
| やったこと | 代筆してよい。事実の記録 |
| 詰まった箇所と、どう解決したか | 代筆してよい。事実の記録 |
| 既に知っている技術との違い | たたき台を出す。本人が直す前提 |
| なぜこの書き方なのか | たたき台を出す。本人が直す前提 |
| **口頭で説明するなら** | **空で渡す** |
| **一度やったはずなのに忘れていたこと** | **空で渡す** |

下2つは本人が書かないと意味がない。代筆すると、読み返したときに自分の理解の記録にならない。
**空欄のまま渡し、「ここは自分の言葉で埋めてください」と伝える。**

## 守ること

- **事実だけ書く。** やっていないことを書かない。試していないコードを「確認した」と書かない
- **長くしない。** 1テーマ1ファイル、画面1〜2枚分まで
- 案件の固有名詞（企業名・システム名・社内独自ライブラリ名）を書かない。公開リポジトリになる可能性がある
- コードを貼るなら要点だけ。全文は貼らない（リポジトリに実物がある）

## 書いたあと

- `git add docs/ && git commit` を促す。**メモのコミットが学習ログになる**
- `explain-check` で「曖昧」と出た項目があれば、それをメモに含める
