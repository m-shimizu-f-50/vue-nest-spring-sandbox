# computed / watch / watchEffect

練習コード：`frontend/src/views/practice/ComputedWatchView.vue`（URL：`/computed-watch`）

## 用語集

### 考え方

- **派生値**: ほかの値から計算して得られる値。例：単価 × 数量 = 小計
- **副作用（side effect）**: 値を計算して返す以外のこと。API の呼び出し、`localStorage` への保存、ログの出力、DOM の直接操作など
- **依存（dependency）**: その計算や処理が読んでいるリアクティブな値。依存が変わると、再計算や再実行が起きる
- **キャッシュ**: 一度計算した結果を保存しておき、次に使い回すこと
- **ソース（source）**: `watch` で監視する対象
- **クリーンアップ**: 前回の副作用を後片付けすること（タイマーの解除、通信のキャンセルなど）。React の `useEffect` の `return () => {...}` に相当
- **Single Source of Truth**: 元になる情報は1か所だけに持ち、そこから作れるものは保存せずに計算する、という状態管理の原則
- **シャドーイング**: 内側のスコープで外側と同じ名前の変数を宣言し、外側の変数が見えなくなること

### Vue

- **`computed`**: 派生値をキャッシュ付きで作る。戻り値は読み取り専用の `ref`。React の `useMemo` に相当（依存配列は不要）
- **`watch`**: 指定した値の変化に反応して、副作用を起こす。古い値も受け取れる。React の依存配列付き `useEffect` に相当
- **`watchEffect`**: 中で読んだ値を全部自動で監視して、副作用を起こす。最初に必ず1回実行される
- **`immediate: true`**: `watch` のオプション。最初にも1回実行する
- **`onWatcherCleanup`**: `watch` / `watchEffect` の中で、次の実行前やコンポーネントが消えるときの後片付けを登録する（Vue 3.5 から）
- **`v-for`**: 配列を繰り返し描画する。React の `array.map()` に相当
- **`:key`**: `v-for` の各要素を見分ける ID。React の `key` と同じルール（一意で、変わらない値）
- **`v-bind`（`:`）**: script の値を HTML の属性に流し込む。一方通行
- **`v-model`**: 入力欄と値を双方向につなぐ

### JavaScript / TypeScript

- **`??`（Null 合体演算子）**: 左側が `null` か `undefined` のときだけ、右側の値を使う
- **`||`（論理和）**: 左側が falsy（`false`、`0`、`''`、`null`、`undefined` など）のときに、右側の値を使う
- **ショートハンドプロパティ**: `{ newValue: newValue }` を `{ newValue }` と書ける省略記法

## 1. computed — 派生値をキャッシュ付きで作る

```ts
const items = ref<Item[]>([
  { id: 1, name: 'チョコ', price: 300, quantity: 2 },
])

const total = computed(() =>
  items.value.reduce((sum, item) => sum + item.price * item.quantity, 0),
)
const totalWithTax = computed(() => Math.floor(total.value * 1.1)) // 重ねてもよい
```

- 戻り値は**読み取り専用の `ref`**。script では `total.value`、template では `{{ total }}`
- 依存は**自動で追跡**される。中で読んだ `ref` / `reactive` が、そのまま依存になる
- **依存が変わったときだけ再計算**。変わっていなければキャッシュを返す
- **中で副作用を起こさない。** いつ・何回実行されるかは Vue が決めるので、API 呼び出しや別の `ref` の書き換えは書かない

## 2. 関数と computed の違い（ステップ2とのつながり）

```vue
<p>{{ calcTotal() }}</p>   <!-- 関数：再レンダリングのたびに毎回計算 -->
<p>{{ total }}</p>         <!-- computed：依存が変わったときだけ計算 -->
```

template は再レンダリングのたびに全体が実行し直される（→ [02](./02-vue3-ref-reactive.md)）。そのため、関数は**合計と関係ない値が変わっただけでも**計算し直される。

### 練習で確かめた結果（console のログ）

| 操作 | 関数版 | computed 版 | 理由 |
|---|---|---|---|
| ページを開いた | 出る | 出る | 最初の描画で、どちらも初めて計算される |
| 「+1」を押した | **出る** | **出ない** | `counter` は合計と無関係。再レンダリングで関数は呼ばれるが、`computed` はキャッシュを返す |
| 数量を変えた | 出る | **出る** | `computed` の依存（`items`）が変わったので、再計算される |

`computed` は「計算しない」のではなく、**「依存が変わったときだけ計算する」**。

**実務での着眼点**：template に `{{ 関数() }}` と書いてあったら、`computed` にすべきではないかを疑う。明細が多い一覧や重い集計だと、入力のたびに画面が重くなる原因になる。

## 3. watch — 指定した値の変化に反応して副作用を起こす

```ts
watch(
  keyword,
  (newValue, oldValue) => {          // 新しい値が先
    keywordHistory.value.push({ id: ..., oldValue: oldValue ?? '', newValue })
  },
  { immediate: true },               // 最初にも実行する
)
```

- **監視対象（ソース）を自分で指定する**
- コールバックの引数は **`(newValue, oldValue)` の順**。直感と逆なので注意
- **最初は実行されない**（`immediate: true` で最初にも実行される）

### ソースの指定方法

| ソース | 書き方 |
|---|---|
| `ref` | `watch(keyword, ...)` |
| `reactive` のプロパティ | `watch(() => form.name, ...)` ← **ゲッター関数で包む** |
| 複数 | `watch([keyword, category], ([newK, newC], [oldK, oldC]) => ...)` |
| `reactive` 全体 | `watch(form, ...)`（中のどれが変わっても反応する） |

`watch(form.name, ...)` と書くと、その時点の値（ただの文字列）を渡すことになり、監視できない。ステップ2の「分割代入すると繋がりが切れる」と同じ理由。

### `immediate: true` と `oldValue` の型

- `immediate: true` を付けると、初回は「前回」が存在しないので **`oldValue` は `undefined`**
- Vue の型定義はこれを反映して、**`oldValue` の型が `string` → `string | undefined` に変わる**
- 型が `string` の項目にそのまま入れると型エラーになる → `oldValue ?? ''` で埋めた

### `??` と `||` の違い

| 値 | `x \|\| ''` | `x ?? ''` |
|---|---|---|
| `undefined` | `''` | `''` |
| `''` | `''` | `''` |
| **`0`** | **`''`（置き換わる）** | `0` のまま |

「`undefined` のときだけ置き換えたい」なら `??`。数量や金額で `||` を使うと、`0` が「値がない」扱いになるバグが起きる。

### 型エラーを消すか、型を実態に合わせるか

`oldValue ?? ''` で埋めると、「前回の値がなかった（初回）」と「前回は空文字だった」が区別できなくなる。区別が必要なら、型を `oldValue: string | undefined` にして画面で「（初回）」と表示する、などの設計にする。**型エラーを見たら、値を埋めるのか、型の方を実態に合わせるのか**の2つを考える。

## 4. watchEffect — 読んだ値を全部、自動で監視する

```ts
watchEffect(() => {
  searchLogs.value.push(`検索：${keyword.value}（カテゴリ：${category.value}）`)
})
```

- ソースを指定しない。**中で `.value` を読んだ値が、すべて自動で依存になる**（`computed` と同じ仕組み）。逆に、中で読まなかった値は変わっても反応しない
- **最初に必ず1回実行される**（依存を集めるため）
- **古い値は受け取れない**（「何を監視しているか」というソースの考え方がないため）
- `await` より後で読んだ値は、依存として追跡されない

### 注意：監視している値を書き換えるとループすることがある

「値が変わったら再実行」の仕組みなので、書き方によっては無限ループになる。Node で実際に確かめた結果：

| 書き方 | 結果 |
|---|---|
| 1つの `watchEffect` の中で、自分が読んでいる値を書き換える（`push` でも `[...arr, x]` の代入でも） | **ループしない**。Vue は、実行中の effect が自分自身を再実行させる変更を無視する |
| `watch` のコールバックで、**自分の監視対象**を書き換える（`watch(n, () => n.value++)`） | **ループする** |
| 2つの `watchEffect` が、**お互いの依存**を書き換え合う | **ループする** |

ループすると `Maximum recursive updates exceeded`（再帰的な更新が上限を超えた）というエラーになる。このエラーを見たら、**監視している値を、監視している側で書き換えていないか**を疑う。

練習の `searchLogs.value.push(...)` は1つ目に当たるので問題ない。ただし、依存を読んで書き換える形は、処理が増えると2つ目・3つ目に変わりやすいので、避けられるなら避ける。

## 5. React との対比

| Vue | React | 違い |
|---|---|---|
| `computed` | `useMemo` | Vue は依存を自動で追跡する。依存配列の書き忘れが起きない |
| `watch` | `useEffect(() => {...}, [keyword])` | Vue は**最初は実行されない**。**古い値**も受け取れる |
| `watchEffect` | 依存を自動で集める `useEffect` | 最初に1回実行されるのは同じ |
| 配列の直接 `push` | `setItems([...items, x])` | Vue は直接書き換えるのが正しい |
| `v-model="item.quantity"`（配列の中を直接） | `setItems(items.map(i => i.id === id ? {...i, quantity} : i))` | Vue は1行で済む |

## 6. 使い分け

| やりたいこと | 使うもの |
|---|---|
| **ほかの値から値を計算したい** | **`computed`** |
| 特定の値が変わったときに副作用／古い値が必要／最初は実行したくない | `watch` |
| 複数の値を使う副作用を最初から実行したい／依存を書き並べるのが面倒 | `watchEffect` |

- **迷ったら、まず `computed` で書けないか考える。** 値を作るだけなら `computed`、それ以外（副作用）なら `watch` 系
- 実務では、**何に反応するかがコードから一目で分かる `watch` の方がよく使われる**。`watchEffect` は中で読んでいる値を全部追わないと、いつ実行されるか分からない

## 7. アンチパターン：watch で派生値を同期する

```ts
// ✕
const fullName = ref('')
watch([lastName, firstName], ([l, f]) => {
  fullName.value = `${l} ${f}`
})

// ○
const fullName = computed(() => `${lastName.value} ${firstName.value}`)
```

### 避けるべき3つの理由（姓 `'山田'`・名 `'太郎'` が初期値の場合）

| 場面 | watch 版で起きること | computed 版 |
|---|---|---|
| **1. 最初から値がずれる** | `watch` は最初は実行されないので、`fullName` は `''` のまま。`immediate` を付け忘れるだけでバグ | 常に `'山田 太郎'` |
| **2. 変えた直後に読むと古い** | `firstName.value = '花子'` の直後に `fullName.value` を読むと `'山田 太郎'`。watch のコールバックは少し後（次の描画の前）にまとめて実行されるため。**「名前を変えてそのまま保存したら、古い名前で保存された」**バグになる | 読んだ瞬間に再計算するので、常に最新 |
| **3. 別の場所から崩される** | `fullName` は普通の `ref` なので `fullName.value = ''` と書けてしまい、「姓・名はあるのにフルネームは空」という状態が生まれる | 読み取り専用。書こうとすると TS がエラー |

**本質は「同じ情報を2か所で持っている」こと。** watch 版は、ずれを後から追いかけて埋めているだけなので、遅れたり崩されたりすると、ずれが表に出る。computed 版は保存せずに毎回計算するので、ずれようがない（Single Source of Truth）。

React で `useEffect` + `setState` で派生値を作るのがダメなのも同じ理由（公式ドキュメント「You Might Not Need an Effect」）。

## 8. v-for と :key

```vue
<ul>
  <li v-for="item in items" :key="item.id">...</li>
</ul>
<li v-for="(log, index) in searchLogs" :key="index">...</li>  <!-- インデックスを受け取る -->
```

- **`<li>` は `<ul>` / `<ol>` の中に置く**（HTML のルール。アクセシビリティにも影響）
- **`:key` は一意で、変わらない値**。名前などの重複しうる値は使わない。実務では DB の ID
- **インデックスを key にしてよいのは、項目の削除や並べ替えがないときだけ**
- ループの変数名が、外の変数と同じ名前にならないようにする（シャドーイング）。`category` が `ref` で使われているなら、ループ側は `option` など

## 9. ハマりどころ

| ハマりどころ | 対処 |
|---|---|
| `:name="keyword"` と書いて入力欄とつながらない | `:`（`v-bind`）は一方通行。入力欄とつなぐのは `v-model` |
| エディタの自動 import が `<script>` の外に入る | ブロックの外は無視されるので、エラーにもならず動いてしまう。**チェックが通っても正しいとは限らない** |
| Emmet の補完で `id=""` が入る | 意味のない空の属性。消す |
| 空配列の `ref([])` から型が推論できない | `ref<Item[]>([])` と型を渡す。API から取るデータは初期値が空なので必須 |
| 入力欄に「12」と打つと、ログが2回出る | 「1」と「2」で2回値が変わるため。正しい動き |
