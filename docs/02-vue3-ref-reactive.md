# ref / reactive と再レンダリングの仕組み

Phase 1 / ステップ2（2026-09-27）

`ref` と `reactive` の違いと使い分け、`.value` が必要な理由、そして **Vue がいつ・どこを描き直すのか**をまとめる。
練習コード：`frontend/src/views/practice/RefReactiveView.vue`（URL：`/ref-reactive`）

## 用語集

### JavaScript

- **Proxy**: JavaScript 標準の機能。オブジェクトへの読み書きに割り込める。Vue はこれで「誰が値を読んだか」「いつ書き換えられたか」を検知している
- **プリミティブ**: `number`・`string`・`boolean` など、オブジェクトではない値。Proxy で包めない
- **スプレッド構文**: `{ ...obj }`。`obj` のプロパティを取り出して、**新しいオブジェクト**に詰め直す。React の state 更新で毎回使っていた書き方
- **シャローコピー（浅いコピー）**: 1段目のプロパティだけをコピーすること。中にあるオブジェクトは共有されたまま。スプレッド構文はシャローコピー
- **ディープコピー（深いコピー）**: 中のオブジェクトまで全部コピーすること。`structuredClone(obj)` で行う
- **イミュータブル／ミュータブル**: 値を書き換えずに新しく作る（イミュータブル）か、今ある値を直接書き換える（ミュータブル）か。React は前者、Vue は後者
- **excess property check**: オブジェクトリテラルに、型に無いプロパティを書いたときに TypeScript が出すエラー。スプレッドを通すと働かない

### Vue

- **`ref`**: どんな値でもリアクティブにできる箱。script では `.value` で読み書きする。React の `useState` に相当
- **`reactive`**: オブジェクトを Proxy で包んでリアクティブにする。`.value` は不要だが、制約がある
- **アンラップ**: `ref` の包みを外して中身を取り出すこと。template の中では自動で行われる
- **`toRefs`**: `reactive` のオブジェクトを、プロパティごとの `ref` に変換する。分割代入しても繋がりを保ちたいときに使う
- **再レンダリング（re-render）**: コンポーネントの template（render 関数）をもう一度実行して、画面を作り直すこと
- **render 関数**: template をコンパイルして作られる、仮想 DOM を作る関数。再レンダリングとは、これを実行し直すこと
- **仮想 DOM**: 画面の構造を表す JavaScript のオブジェクト。前回と比べて、差分だけを実際の DOM に反映する
- **`v-model`**: 入力欄と値を双方向につなぐディレクティブ。React の `value` と `onChange` をまとめて書いたもの
- **修飾子（modifier）**: `v-model.number` のように、ディレクティブの動きを変える指定
- **Vapor Mode**: Vue 3.6 で導入予定の、仮想 DOM を使わない描画方式。値を使っている DOM の1か所だけを直接書き換える

## 1. ref — どんな値でも包める箱

```ts
const count = ref(0)                    // Ref<number>
const currentUser = ref<User>({ name: '', age: 0 })

count.value++                           // script では .value
currentUser.value = { ...sampleUser }   // 丸ごと差し替えられる
```

```vue
<p>{{ count }}</p>                      <!-- template では .value 不要（自動アンラップ） -->
```

### なぜ `.value` が必要なのか

Proxy が割り込めるのは**オブジェクトの読み書きだけ**。`0` のようなプリミティブには割り込めない。
そこで `ref` は値を `{ value: 0 }` のようなオブジェクトに包み、`.value` への読み書きを検知できるようにしている。
**`.value` は「Vue に変化を知らせるための入口」。**

## 2. reactive — オブジェクトをそのままリアクティブにする

```ts
const userInfo = reactive<User>({ name: '', age: 0 })
userInfo.name = 'Alice'                 // .value なしで書ける
```

### 3つの制約

| 制約 | 例 | 何が起きるか |
|---|---|---|
| オブジェクトしか渡せない | `reactive(0)` | 型エラー |
| **丸ごと代入できない** | `let u = reactive(...)` → `u = 別のオブジェクト` | Vue に伝わらない。Proxy との繋がりが切れる |
| **分割代入すると繋がりが切れる** | `const { name } = userInfo` | `name` はただの値のコピー。入力しても表示が変わらない（→ 必要なら `toRefs`） |

## 3. ref と reactive の使い分け

**Vue 公式の推奨は「基本は `ref`」。** ただし現場のコードには `reactive` も普通に出てくる（特にフォームの値をまとめるとき）。

| 使いどころ | おすすめ |
|---|---|
| 数値・文字列・真偽値 | `ref` |
| API から取ってきて丸ごと差し替えるデータ | `ref` |
| 差し替えずに、項目を書き換えていくだけのオブジェクト | `reactive` でもよい |
| **画面に出さない・書き換えないデータ**（サンプルデータ、定数） | **リアクティブにしない**。普通の `const` |
| 迷ったら | `ref` |

**宣言は必ず `const`。** `const` が禁止するのは「変数への再代入」だけで、`.value` やプロパティの書き換えはできる。`let` を使いたくなったら、`ref` を使うべきサイン。

## 4. React との対比

| | React | Vue |
|---|---|---|
| 宣言 | `const [count, setCount] = useState(0)` | `const count = ref(0)` |
| 更新 | `setCount(c => c + 1)` | `count.value++` |
| オブジェクトの更新 | `setForm({ ...form, name: 'Alice' })` | `form.name = 'Alice'` |
| 考え方 | 新しい値に置き換える（イミュータブル） | 今ある値を直接書き換える（ミュータブル） |
| スプレッドが必要な場面 | ほぼ毎回 | **同じオブジェクトを共有したくないときだけ** |

**React から戻ってくるときの最大の切り替えポイント**：Vue では**直接書き換えるのが正しい**。書き換えを Proxy が検知して、画面を更新してくれる。

## 5. オブジェクトの共有とコピー

```ts
const sampleUser: User = { name: 'まさと', age: 31 }  // 書き換えないので ref にしない

const replaceUser = () => {
  currentUser.value = sampleUser          // ✕ 同じオブジェクトを指す
  currentUser.value = { ...sampleUser }   // ○ 毎回コピーを渡す
}
```

`✕` の書き方だと、`currentUser` を編集したときに **`sampleUser` 側まで書き換わる**。
業務でいうと「初期値に戻す」ボタンが、編集後の値に戻してしまうバグになる。

```ts
const a = { name: 'まさと' }
const b = a          // 代入：同じオブジェクト（a === b は true）
const c = { ...a }   // スプレッド：別のオブジェクト（a === c は false）
```

- スプレッドは**シャローコピー**。中にオブジェクトがあれば、それは共有されたまま → 必要なら `structuredClone`
- サンプルデータには `: User` と型を付ける。スプレッドを通すと excess property check が働かないので、宣言の時点で型を付けておかないとタイプミスを見逃す

## 6. 再レンダリングの仕組み

### 「だけ → 全体 → だけ」

```
値が変わる
   ↓
① その値を使っているコンポーネントを探す      ← 使っているコンポーネント「だけ」
   ↓
② そのコンポーネントの template 全体を実行し直す ← template「全体」
   ↓
③ 前回と比べて、変わった DOM だけを書き換える   ← 変わった DOM「だけ」
```

**一言でいうと：更新された値を使っているコンポーネントの template に、再レンダリングがかかる。**

- 「使っている」＝再レンダリングのときに読んでいる。script で宣言しただけで template で読んでいない値は含まれない
- 使っているコンポーネントは1つとは限らない（store の値を複数のコンポーネントが表示していれば、全部）

### script は再実行されない

| 元のブロック | 変換後 | 実行されるタイミング |
|---|---|---|
| `<script setup>` | `setup()` 関数 | インスタンスが作られるときに**1回だけ** |
| `<template>` | render 関数 | **再レンダリングのたびに毎回** |

- 関数の**定義**は1回だけ → React の `useCallback` に相当するものは不要
- ただし template の中で**呼んでいる関数**（`{{ formatName(user) }}`）は毎回実行される → 重い計算は `computed` にする（ステップ3）

### 子コンポーネントは props が変わったときだけ

親が再レンダリングされても、子は次のどちらかのときだけ再レンダリングされる。

- 親から渡される **props が変わった**
- 子自身が、変わった値を読んでいる

| | React | Vue |
|---|---|---|
| 親が再レンダリングされたとき、子は？ | 全部再レンダリング | props が変わった子だけ |
| 無駄な再レンダリングを防ぐには | `React.memo`、`useCallback` | 何もしなくてよい |
| 再レンダリングで再実行されるもの | コンポーネント関数の全体 | template（render 関数）だけ |

**注意**：props の比較は `===`（浅い比較）。template の中で `:user="{ ...currentUser }"` と書くと、毎回新しいオブジェクトになり、子も毎回再レンダリングされる。コピーは script の中で必要なときに1回だけ作る。

### 参考：Vapor Mode（Vue 3.6）

②をなくし、値を使っている DOM の1か所だけを直接書き換える方式。安定版（3.5 系）と現場のコードは①②③の仕組みで動いている。

## 7. ハマりどころ

### `let` に代入しても画面が変わらない（のに、別の操作で急に変わる）

```ts
let userInfo = reactive({ ... })
const change = () => { userInfo = 別のオブジェクト }  // 押しても画面は変わらない
```

このあと別の `ref`（例：カウンター）を変更すると、**差し替えた内容が急に表示される**。

- `let` への代入は Vue に気づかれない → 再レンダリングのきっかけにならない
- 別の `ref` が変わってコンポーネントが再レンダリングされると、template が変数の「今の中身」を読み直す → 裏で差し替わっていた新しいオブジェクトが表示される
- **React で `useRef` を直接書き換えたあと、別の `setState` で急に反映される現象と同じ**

**教訓：画面に反映されたからといって、Vue がその変化を検知できているとは限らない。**
「別の項目を触ると反映される」「保存を押すと表示が直る」というバグ報告を受けたら、**リアクティブでない値を書き換えていないか**をまず疑う。

### その他

| ハマりどころ | 対処 |
|---|---|
| script で `.value` を付け忘れる | TS がエラーを出してくれる（`Ref<number>` は数値ではない） |
| `reactive` を分割代入する | 繋がりが切れる。必要なら `toRefs` |
| `reactive` を丸ごと差し替えたくなる | `ref` を使うべきだったサイン |
| `<input type="text" v-model="user.age">` で `age: number` に文字列が入る | **TS は検出しない。** `type="number"`（Vue 3 では自動で数値に変換）か `v-model.number` を使う。ただし空欄にすると `''` が入る |

## 8. 命名の目安

| 種類 | 形 | 例 |
|---|---|---|
| `ref` / `reactive` / データ | 名詞 | `count`、`currentUser`、`sampleUser`、`form` |
| 関数 | 動詞から始める | `increment`、`reset`、`replaceUser` |
| 真偽値 | `is` / `has` / `can` で始める | `isLoading`、`hasError` |

- `userInfo2` のような番号付きの名前は避ける（何が違うのか分からない）
- `Info` / `Data` / `Obj` は情報量がほぼない。`User` 型なら `user` で十分
- ルートの `name` は ID なので、ページごとに一意にする（`'practice'` のような汎用的な名前は、ページが増えるとぶつかる）
